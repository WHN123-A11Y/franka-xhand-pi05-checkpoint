# 真机接口与验证状态

本工程当前提供的是**离线预测**，没有已经验证的 Franka/XHand 控制器连接、实时相机采集、闭环轨迹执行或任务成功率。`src/offline_inference.py` 读取记录样本，输出模型结果，不连接硬件。

## 设备侧需要核对的信息

请设备负责人结合自己的控制器、SDK 与实际安装确认：

1. `head_view`、`front_left_view`、`wrist_view` 的相机标识、安装朝向、时间戳、同步和图像预处理。前左相机物理上不是左腕相机，虽然模型槽位名是 `left_wrist_0_rgb`。
2. 7 个机械臂和 12 个 XHand 关节的状态与命令字段顺序、单位、方向、零位、限位、耦合及 XHand 控制模式。原始数据的 19 维位置不等于已确认与当前控制器逐项一致。
3. 观测与动作使用所选 checkpoint 的 `assets/xhand_local/norm_stats.json`；原生预处理进行 q01/q99 归一化，输出需对应逆变换，避免重复处理。越过训练数据范围时需要单独检查。
4. 10 步动作块如何选择与执行、重观测和推理的周期、延迟、超时、无效输出、通信丢失处理。20 Hz 只是数据记录率，不是已验证的真机控制周期。
5. 具体设备既有的限速、碰撞检查、急停、通讯及异常处理；此项目未验证其参数，也不提供可直接执行的真实机器人控制器。

## 建议验证顺序

先使用根目录 `README.md` 所述记录样本，在不连接硬件的条件下安装、解压并运行离线重放。检查配置、输入图像、两类目标在三视角的框和接受状态、候选分数融合、动作数组 shape、是否为有限值及参考对照。模型输出中内部归一化 `native/zero/k4` 是 10×32；逆归一化的 `*_recorded_units19` 是数据记录口径的前 19 维，不能未经设备核对就下发。

完成离线检查后，针对实际控制接口设计适配层，并由设备负责人按已有实验规范验证。实验对比需明确保存模型 checkpoint 与 SHA、相同初始状态、原始观测和任务指令、Student 框及接受状态、实际条件和输出动作、设备反馈、接触和最终成功/失败。这样才可以研究区域条件对真实动作的影响；记录样本的预测误差不足以证明真机提升。

`experiments/` 中的原生脚本是训练参考，含原服务器路径，无法凭存在而宣称新机器上可直接训练。`models/student/best.pt` 只包含定位和候选框验证头的有效训练；视角有效性与分布头未训练。请勿基于随机头输出做真机视角选择，也不要将未经对照的人为示意图称为真实测试结果。
